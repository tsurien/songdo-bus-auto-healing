# 송도 버스 도착 안내 및 자동 복구 프로젝트 작업목록

**이 문서의 용도:** 승인된 PRD를 구현·검증할 작업으로 나눈 초안입니다. 전체 흐름은 4절, 상세 작업은 5절, 요구사항 연결은 6절에서 확인합니다. 상세 작업목록은 승인됐습니다.

**현재 단계: 기획.** 코드 작성·테스트 실행과 인천 API·Gemini·Supabase·Redis 연결은 보류합니다. 아래의 개발 순서는 팀이 나중에 구현을 재개할 때 참고하는 계획입니다. 이전에 수행한 작업과 검증 결과는 각 항목에 기록돼 있습니다.

**포지션별 읽기 안내:** 프론트엔드는 시민·운영 화면(3·6번), 백엔드는 수집·저장·복구(1·2·5번), AI 담당은 안내 생성·진단(4번)을 먼저 확인합니다. 통합 검증과 데모(7번)는 팀이 함께 확인합니다. 이는 읽기 안내이며 4명의 담당자 배정을 확정한 것은 아닙니다.

## 2. 프로젝트 목표

송도센트럴파크역 38563번 정류소의 버스 도착정보를 제공하고 장애를 탐지·진단·제한 복구한 뒤 독립 검증합니다. 같은 인천 공공 버스 API로 이전 버스 기록의 수집·저장·조회가 필수입니다. 기록을 아직 확보하지 못했으면 “이전 버스 기록 없음”으로 표시하되 필수 기능의 완료로 간주하지 않습니다.

## 3. 작업 원칙

- PRD의 포함·제외 범위를 따릅니다. 첫차·막차, 지도·경로 탐색, 유료 API와 실제 교통 시스템 변경은 제외합니다.
- 작업은 한 번에 하나씩 실행하고 검증 증거를 남깁니다. 구현 작업은 아래의 개별 상태를 따릅니다.
- 각 작업의 완료는 해당 검증과 PRD 인수조건을 충족하고 결과를 기록했을 때 판단합니다. 검증 결과는 통합 단계에서도 활용해 같은 확인을 불필요하게 반복하지 않습니다. 자동 테스트와 화면·API 확인을 작업 특성에 맞게 사용합니다.
- API 키를 대화나 저장소에 넣지 않습니다. 외부 배포, 원격 push와 메시지 전송은 별도 승인 후 실행합니다.
- 실제 연동이 준비되지 않으면 모의 데이터부터 확인하되 실제 연동 완료로 표시하지 않습니다.
